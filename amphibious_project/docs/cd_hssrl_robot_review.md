# CD-HSSRL 机器人模型核查及本工程接续方案

核查日期：2026-10-27。依据用户提供的本地仓库文件，不将这些配置自动视作论文最终实验配置。

## 仓库确实给出了机器人模型

`uuv_simulator-noetic/ky_3/urdf/` 提供 URDF/Xacro，`ky_3/meshes/` 提供 STL。
模型包含机体、轮子、八个推进器的几何与安装关系、质量惯量、碰撞和 Gazebo/UUV 插件。
螺旋桨不靠可视网格旋转来计算流体推力，插件另行施力；这种建模方法本身不能简单判为错误。

README 指定的启动文件是 `ky_3/launch/complex_world_without_ultrasonic.launch`。
其实际加载 `ky_3_without_ultrasonic.xacro`，而不是 `ky_3.xacro`。

| 核查项 | ky_3_without_ultrasonic.xacro | ky_3.xacro |
| --- | --- | --- |
| 机体 base_link 质量 | 40 kg | 10 kg |
| 显式轮子 continuous 关节 | 左右各 5 个，共 10 个 | 左右各 2 个，共 4 个 |
| 推进器宏实例 | 8 个 | 8 个 |
| UUV 排水体积 | 0.0475 m³ | 0.0155 m³ |
| 浮心 | (0,0,0.12) m | (0,0,0.25) m |
| 水密度 | 1028 kg/m³ | 1028 kg/m³ |
| 附加质量平动对角项 | 4.5,300,300 | 10.5,24.7,28.57 |

不能拿前一列的机器人外观，套用后一列的质量、水动力参数后宣称复现了同一个模型。
40 kg 是 base_link 质量。该 Xacro 顶层显式 link 的质量合计约 47.62 kg；
推进器宏还会生成内容，完整整机质量应以展开后的 URDF/SDF 及运行时结果为准。

十轮配置使用 `libgazebo_ros_skid_steer_drive.so`，并声明了中间轮关节参数。
复现时还应验证实际插件版本是否处理这些额外关节，不能只根据 Xacro 字段认定十轮均已受控。

## 几何量级

按二进制 STL 三角顶点逐一计算，`base_link.STL` 的包围盒约为：

- X：-0.47903 到 0.46500 m，长 0.94403 m；
- Y：-0.29152 到 0.29152 m，宽 0.58304 m；
- Z：-0.00017 到 0.38500 m，高 0.38517 m。

该文件有 748,584 个三角面。因此“研究设定简单”不等于“CAD 网格简单”。
导航研究更应关注动力学、模式切换机制、环境变化和验证覆盖，而不是增加模型面数。
自己的模型应分开制作显示网格和简化碰撞几何。

## 简化训练环境与 Gazebo 不能当作同一物理仿真

`CD-HSSRL Code/e2e_resumable.py` 实例化的是 `AmphibiousSimEnv`，未加载上述 Gazebo 机器人。
`env/amphibious_sim_env.py` 中的关键处理是：

1. 使用固定的质量、体积和阻尼常量，另行定义二维运动。
2. 陆地速度采用一阶跟踪，偏航直接按角速度指令积分。
3. 水域的返回速度将垂直速度置为零，偏航仍直接按角速度指令积分。
4. step() 内另用浮力表达式更新高度并对地形取 max；这不是完整的垂直速度—加速度积分。
5. 地形主要是随 X 变化的水域、单一线性过渡带、陆地；域标签主要用高度阈值判断。

因此它适合快速验证策略接口，但不足以验证真实履带打滑、部分浸水浮力力矩、搁浅、
推进器出水失效和上下岸姿态稳定性。Gazebo 那条实现路线本身比此简化环境更丰富，
也需要独立复现与检查。不能仅依据 NumPy 环境就断言论文所有结果使用了同样的简化。

## 本工程当前完成到哪里

`river_forest_v1.usda` 是自己的程序生成环境：32×72 m，弯曲河道、变化水深、
不同干湿岸坡、低摩擦泥地、树干和岩石碰撞，以及三个起终点任务定义。
浅滩与缓坡在南段，中央东岸更陡，北段设有另一处较缓上下岸区域及泥地。

水面只是非碰撞可视表面；没有以蓝色平面代替浮力，也未声称已具备水动力。
当前没有放入机器人，没有运行导航或模式切换算法。场景复杂化先提供可控的环境变量，
实际能否形成更有价值的研究，仍需完成机器人动力学和系统性对照实验。

## 自己的机器人下一步如何接入

机器人继续使用用户指定的双履带、双水平推进器结构。
`configs/robot_prototype_plan.json` 给出约 1 m 机体的初始可调量级，全部标注为设计初值。
没有复制 CD-HSSRL 的网格、八推进器分配器或策略代码。

下一阶段需分别建立并验证：

1. 机体质量、惯量、重心、碰撞和履带接地；若先用滚轮接触近似履带，须明确标注，不能当成完整履带链。
2. 分布式浸水体积、浮力及浮心，允许接地力与浮力同时存在。
3. 相对水流的线性/二次阻力；附加质量视标定与稳定性需求逐步加入。
4. 双推进器的推力曲线、响应时滞、浸水有效系数和左右差动偏航力矩。
5. 先验证直行、转向、静水漂浮和上下岸，再接入导航/切换算法。

未来按物理步记录位姿、速度、姿态、接触、浸水、两套执行器命令和能耗代理量。
不能把“每个路点”直接等同于固定时间的决策步；各控制频率和策略频率应独立设置。

## 这次测试做什么

在自己的 `river_robot_v1.usda` 场景，走南侧预留的缓坡通道：起点 `(-12, -23)` 米，终点 `(12, -23)` 米，路线长 24 米。

物理频率 120 Hz，控制频率 20 Hz。参考速度：陆地 0.45 m/s、过渡 0.35 m/s、水中 0.70 m/s。推进器最大推力、摩擦、浮力和时滞沿用现有机器人参数。只在开始前设初始位姿；运行期间只输出两条履带的速度和两个推进器的归一化推力。位姿、接触和运动由 PhysX 计算。

模式由接触载荷、浮力和当地水深判定，并带滤波和最短驻留时间。这是人工编写的运动检查基线，后续可以替换为待测模型。不会仅根据机体原点是否低于水面判断入水，因为该机器人的漂浮平衡原点在水面上方约 3.54 厘米。

## 上传和安装

服务器有人使用时保持不运行。空闲后，只把 `crossing_update_20261028.zip` 上传到自己的 `/home/ubuntu/L17/`。

这个 ZIP 内有 Python 安装入口，可以直接执行：

```bash
python3 /home/ubuntu/L17/crossing_update_20261028.zip
```

安装前会校验既有机器人和场景的文件指纹。如果它们后来被改过，安装会停止，列出需核对的文件，不覆盖现有环境。更新增加测试文件，并为自己的启动器增加可选显卡参数；既有同名文件会先备份到本工程 `.runtime/crossing_update_backups/`。不会下载软件或启动仿真，不会修改共享 Isaac Sim。

## 一条命令开始完整过河

连接 ToDesk 桌面并确认显卡空闲后，在服务器终端输入：

```bash
python3 /home/ubuntu/L17/amphibious_project/scripts/run_crossing.py --start
```

这会新开自己的测试窗口，加载场景并自动执行，结束后保存结果并关闭这次新开的窗口。它会沿用工程原有的隔离启动器，将 L17 以外的持久目录设为只读。

若自己的旧 Isaac 窗口还开着，先在界面关闭那一个窗口。脚本不会关闭任何已有程序。默认只使用 GPU0 做显示，物理计算沿用 CPU；启动器的 CUDA 设备参数也与 GPU0 对齐，避免默认参数指向 GPU1。默认发现 GPU0 显存占用超过 2048 MiB 或利用率超过 25% 时拒绝开始。这只是启动时检查，不能替代共享服务器的资源预约。

想在结束后留住最终画面，使用：

```bash
python3 /home/ubuntu/L17/amphibious_project/scripts/run_crossing.py --start --keep-open
```

只检查文件、查看当前状态、请求停止分别使用：

```bash
python3 /home/ubuntu/L17/amphibious_project/scripts/run_crossing.py --check
python3 /home/ubuntu/L17/amphibious_project/scripts/run_crossing.py --status
python3 /home/ubuntu/L17/amphibious_project/scripts/run_crossing.py --stop
```

`--stop` 只对本次测试写停止请求；也可在测试窗口按暂停。失败或主动中止时下发零指令、暂停物理仿真并保留数据。默认自动关闭自己的测试窗口；`--keep-open` 时保留。

## 何时算通过

必须同时有这些真实仿真记录：

- 从陆地实际承重开始，入水后有浮力；
- 累计至少 1 秒处于浮力承担至少 80% 自重、履带承重小于 8% 自重的漂浮状态；
- 漂浮期间两个推进器合计有效推力超过 2 N；
- 到达对岸陆地，重新主要由地面承重；
- 距终点不超过 0.6 米，水平速度低于 0.1 m/s 并保持 0.6 秒；
- 未与树干、岩石碰撞，未触发姿态、速度、时间和控制周期限制。

连续 12 秒沿路线推进不足 0.15 米、翻滚超 35°、俯仰超 38°、过度下沉、驶出地形、150 秒仿真超时等情况，均停止并保存具体原因。启动失败与过河失败分别记录，不能把模型加载错误算成机器人过河失败。

## 自动保存什么

每次写入独立目录 `/home/ubuntu/L17/amphibious_project/results/crossing/run_日期_时间_编号/`：

| 文件 | 内容 |
|---|---|
| `summary.json` | 总体通过与否、每项判据、失败原因、耗时、路程、姿态、漂浮时长、切换次数、源文件指纹 |
| `physics.csv` | 约 120 Hz 的实际位姿、速度、浮力、接触载荷、牵引力、有效推力和执行器命令 |
| `commands.csv` | 20 Hz 的目标路点、速度参考、选择的模式和下一步四个执行器命令 |
| `route_preflight.json` / `route_profile.csv` | 路线、水深、坡度、摩擦和障碍物间隙检查 |
| `progress.json` | 当前阶段及最近状态 |
| `crossing_report.svg` | 实际轨迹、高度、承重、速度和模式时序，可用浏览器打开 |
| `final_view.png` | 最终场景截图；截图失败不改变运动判定 |
| `01_entering_water.png`、`02_swimming.png`、`03_landing.png` | 根据浮力、接触和位置触发的入水、水中和上岸照片；暂停取景后继续，不改变位姿 |
| `checkpoint_photos.json` | 三张照片的物理时间、原生位姿、速度、接触和浮力证据 |

`commands.csv` 时间是作出决策的观测时间，新命令从下一物理步开始生效，延迟最多约 1/120 秒。机械功与推进器理想功率的积分只是能耗代理量，不是电池电量。

退出码：0 为完整过河通过；2 为已运行但未通过；3 为未能启动或准备检查失败。启动导入错误查看本工程 `.runtime/crossing_startup_error.txt`，详细应用日志在 `.runtime/logs/`。
